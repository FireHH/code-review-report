# 代码规范

审查某个项目前，把本文件复制到该项目根目录，并命名为 `code-review-standards.md`。也可以放到 `.cursor/code-review-standards.md`。只保留这个项目真正要执行的规则。

## 必须

违反这里的规则时，审查报告至少记为 medium。若同时构成缺陷、隐患或漏洞，归到对应小节，不要再记一条规范问题。

- 使用对象、集合元素、查询结果和外部输入之前，要处理空值。
- 分支要覆盖业务上的失败和边界，不能只写成功路径。
- 捕获异常后不能忽略并继续当作成功。
- 不要把密钥、口令和连接串写进源码。

## 建议

只违反这里的规则时，记为 low。

- 循环内不要逐条访问数据库或远程接口。
- 对外方法注明参数是否允许为空。
- 批量接口要有分页或数量上限。

## 不审查

- `node_modules`、`vendor`、`dist`、`build`、锁文件和生成代码。
- 与本次改动无关的历史文件，除非明确要求全仓审查。
