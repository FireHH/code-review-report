# 缺陷与隐患检查清单

只根据读到的代码判断。同一处问题只归入一个小节。

## 缺陷

记入「缺陷」，编号 `BUG`。这是已经能从代码看出的错误行为。

- 空指针和空值：对可能为空的对象、数组元素、查询结果、可选配置直接取字段或调用方法，并且调用方没有保证非空。
- 逻辑错误：条件写反、边界差一、分支缺失、互斥条件重叠、错误的运算符或比较对象。
- 结果错误：返回值、状态码、默认值与方法名或调用方约定不一致；循环提前结束或永远到不了更新。
- 错误被当成成功：捕获异常后忽略，再返回成功或继续使用未完成的数据。
- 资源在失败路径上没有释放，后续调用会读到脏状态或句柄耗尽。

## 隐患

记入「隐患」，编号 `RISK`。当前路径还不能证明一定出错，但存在明确的失败条件。

- 外部输入、空集合、空字符串没有校验就进入后续计算。
- 类型转换、下标和除法没有处理失败或零值。
- 并发下共享集合被一边遍历一边修改，或检查与使用之间状态会变。
- 只处理了正常返回，超时、部分失败和重试后的重复执行没有收尾。
- 注释或未完成标记下面留着会进入生产路径的临时代码。

## 归类

- 已经造成错误结果或必然会抛出空指针：缺陷。
- 依赖特定数据才会出错：隐患。
- 会泄露数据、绕过权限或执行不可信输入：改记入漏洞，不重复记缺陷。
- 只是变慢：改记入可优化项。
- 只违反项目自定义规范，还构不成上面几类：改记入规范。

## 不报告

- 没有调用链、只凭变量名猜测可能为空。
- 语言或框架已经保证非空的位置。
- 测试夹具里故意的空值，且生产路径到不了。
