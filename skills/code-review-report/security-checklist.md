# 安全检查清单

只根据读到的代码判断。发现问题时记录类别、位置、影响和防御修复。不要编写利用方法。

## 输入与注入

- SQL、NoSQL、LDAP、命令、模板是否把外部输入拼进查询或命令。修复用参数化、转义或允许列表。
- 路径是否由外部输入拼接，能否跳出预期目录。修复用规范化后的前缀校验。
- 反序列化是否接受不可信数据并还原成对象。修复用显式字段映射，不用任意类型还原。

## 认证、会话与授权

- 敏感操作是否在服务端检查登录态，而不是只靠前端隐藏。
- 对象访问是否核对当前用户与资源的所属关系，避免只靠客户端传来的标识。
- 会话、令牌、Cookie 是否有过期、绑定和传输保护。密码是否以可逆方式保存。

## 敏感数据

- 密钥、口令、连接串、私钥是否出现在源码、配置样例或日志里。
- 错误响应和日志是否回显内部路径、堆栈、令牌或查询语句。
- 敏感字段是否在不需要的接口里返回。

## Web 与浏览器

- 输出到 HTML、属性、URL 或脚本上下文时是否做了对应编码。
- 会改变状态的请求是否能被其他站点直接触发。修复用服务端校验的反伪造令牌和同源策略。
- 文件上传是否限制类型、大小和保存位置，并避免把上传内容当作可执行文件提供。

## 网络与依赖

- 服务端请求的目标是否由外部输入决定。修复用允许列表和禁网段策略，并禁止跟随不可信重定向。
- 依赖是否调用了已知不安全的 API，或关闭了证书、主机名校验。
- 加密是否使用项目所在平台当前推荐的算法和合适的随机源。不要自己设计算法。

## 不报告

- 没有调用链证据的「可能有风险」。
- 只存在于测试夹具、且生产路径到不了的示例。
- 需要先泄露另一个未在代码中出现的密钥才能成立的猜测。
