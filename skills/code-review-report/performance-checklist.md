# 性能与资源检查清单

只报告能指出具体代码和代价的项。说明触发条件和预期收益。

## 数据访问

- 循环或逐条渲染里是否各发一次查询、远程调用或文件读取。
- 是否一次加载全表、全文件或无分页列表，而调用方只使用一小部分。
- 是否缺少与查询条件匹配的过滤，导致先取出再在内存里筛选。
- 事务、连接、游标、文件句柄是否在所有路径上释放。

## 复杂度与热路径

- 请求处理、定时任务或用户可触发的循环是否是可避免的平方或更高复杂度。
- 相同输入是否在同一次请求里重复计算，且结果足够大或足够慢。
- 同步阻塞调用是否卡在会并发执行的请求路径上。

## 内存与负载

- 是否把无界输入收进单个字符串、数组或缓冲区。
- 缓存是否没有容量上限、过期或失效条件。没有这些条件时，不要建议加缓存。
- 重试是否没有次数、退避和抖动，可能在故障时放大流量。
- 超时是否缺失，导致一个慢依赖拖住调用方。

## 前端与批处理

- 大列表是否没有分页或窗口化。
- 是否在渲染路径上做重复的大对象拷贝或深层比较。
- 批处理是否没有分批大小，一次处理的记录数随输入增长。

## 不报告

- 把局部变量提出来、改成更快的写法但复杂度不变的微优化。
- 没有调用频率或数据量说明的「可以缓存」。
- 只在启动或极少执行路径上出现、且成本很低的写法。
