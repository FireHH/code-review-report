# 审查报告

按 `code-review-report` 技能审查代码，并生成报告。

1. 范围使用用户在命令后写的路径或说明。没有说明时，审查当前未提交改动；没有改动时，审查当前分支相对基线的差异。
2. 检查空指针、逻辑错误、bug、隐患、漏洞、效率问题，以及项目规范和 `.cursor/rules`。用户如果只要其中一类，其余小节写 `未审查。` 并说明原因。没有任何规范文件时，「规范」写 `未审查。`。
3. 没有未提交改动、分支差异为空，且用户没有指定路径时，说明没有可审查的改动，不要扩大到全仓。
4. 把报告写到项目的 `code-review-reports/` 目录。每条发现给出改前和改后；规范问题引用具体条款。
5. 校验通过后，回复报告路径和各级数量。
